# Practical 10
CP1404 Practical Reflection



How was your estimate accuracy usually?
- I'd say my estimates were in the ballpark but often a bit off. 
I usually underestimated how long debugging would take, especially when working with new libraries or APIs. 
The coding part itself I could estimate fairly well, but those unexpected issues always popped up.

How did your estimate accuracy improve or change during the course of the subject?
- I definitely got better as we went along. 
Early on, I'd just guess how long something might take, but by the end, I was properly breaking tasks down and adding buffer time for problem-solving. 
I learned to expect the unexpected when it comes to coding tasks.

What did you learn from doing these estimates?
- I learned that good estimating is a skill that takes practice. 
Breaking things into smaller steps makes a huge difference, and tracking actual vs. estimated time helps you see where you tend to underestimate. 
It's actually been useful for other subjects too.
Code Reviews

What have you learned from being reviewed by other people?
- Having others look at my code was really valuable. It taught me that what makes sense to me might not be clear to others. 
I learned to write more readable code with better comments.
People often spotted little issues I'd missed, especially around edge cases.

What have you learned from doing code reviews of other people?
- Reviewing other people's code improved my own coding. 
I saw different approaches to the same problems and picked up some good techniques. 
It also helped me learn to give constructive feedback - pointing out issues but also suggesting solutions.
